# Live UI review — September 9, 2026

Baseline reviewed: `3c068eb1af3084d93893106f4aa719df8a345c99`, the verified Pages release after PR #41.

The hosted screenshot artifact for all primary routes was reviewed before this branch was created. The application was functionally rich but visually flat: page widths were loose, navigation and headings lacked hierarchy, Carrier 360 pages repeated equally weighted white cards, complete-data status dominated every drillthrough, summary copy was difficult to scan, native meter charts looked browser-default, carrier/evidence tables had weak row and header hierarchy, and state maps were hidden behind an explicit date-window action.

This branch is a presentation-focused pass. It does not change FMCSA query predicates, source identities, evidence completeness semantics, scoring availability, SMS rules, warehouse behavior, or provenance classifications.

Implemented presentation changes:

- unified navy/orange/slate design tokens, spacing, radii and shadows;
- stronger sticky global navigation and page hierarchy;
- improved Overview cards without changing information architecture;
- redesigned carrier filter controls, KPI strip and carrier summary table with sticky headers, zebra/hover states and compact evidence links;
- Carrier 360 identity hero, exposure metrics, report actions and sticky tab treatment;
- compact complete-data loading/verification ribbon;
- At-a-glance paragraphs converted into scannable evidence cards;
- browser-native meter charts replaced with branded proportional bars;
- new recent state-level inspection/crash map on Safety, visible without applying a custom window;
- upgraded selected-window map with state intensity, layer toggles, ranked states and event drillthrough;
- inspection and VIN drillthrough metric summaries;
- improved inspection/VIN/native evidence tables and complete-evidence record browser;
- scoped print/report overrides so app-scale map/chart styling does not degrade the existing three-page report layout.

Map precision remains intentionally state-level. No event coordinates are fabricated and no third-party geocoding was introduced. Inspection state can fall back to reporting jurisdiction and is labelled as such. Crash involvement continues to be described as involvement rather than fault.

Acceptance requires the existing full CI suite, production build, protected-main merge, Pages deployment, hosted SHA verification, live route rendering, and new hosted screenshots before this branch can be described as production complete.
